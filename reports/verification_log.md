**Environment**

| Python | 3.13, in a project-local `.venv` |
| Dependencies | `pip install -r requirements.txt` completed successfully |
| Dependency consistency | `python -m pip check` → `No broken requirements found.` |

**Runs and outcomes**

| Command | Outcome |
|---|---|
| `python tests/test_pipeline_offline.py` | **PASSED 67/67 checks** |
| `python tests/test_app_offline.py` | **PASSED 25/25 checks** |
| `python scripts/smoke_test.py --fixtures` | **`PASS - every pipeline stage ran end to end.`** |

Total offline checks passing: **92/92**.

**What the smoke test established**

* The real embedding model `sentence-transformers/all-MiniLM-L6-v2` downloaded
  from Hugging Face and loaded successfully.
* Real embeddings were generated. Embedding dimension confirmed as **384**,
  matching the model's documented output size.
* A real FAISS `IndexFlatIP` was built over those embeddings, searched, saved
  to disk and reloaded, with the reload returning identical results.
* 3 synthetic fixture PDFs produced **14 chunks** with intact
  document / page / chunk-id metadata.
* Retrieval results were judged semantically sensible for the synthetic fixture
  questions by manual inspection.

**What this run did NOT establish**

* **The corpus was synthetic.** All three documents were generated by
  `scripts/make_test_pdfs.py`. Their content is fabricated and carries a
  "SYNTHETIC TEST DOCUMENT" banner on every page. No real biomedical paper has
  been ingested.
* **No retrieval quality was measured.** "Semantically sensible" is an informal
  visual judgement on a 14-chunk toy corpus, not a metric. Recall@1, Recall@3,
  Recall@5 and MRR remain **unmeasured**.
* **Real-PDF ingestion is untested.** Synthetic fixtures are single-column,
  cleanly generated text. They exercise none of the conditions that actually
  break PDF extraction: two-column layouts, running headers and footers,
  reference lists, tables, figure captions, footnotes, ligature-heavy
  typesetting.
* **Chunking parameters are unvalidated.** `chunk_size=1000` / `overlap=175`
  were chosen as reasonable defaults, not tuned. A 14-chunk corpus cannot
  indicate whether they are right for real papers.
* **Generation is unverified.** The app ran in retrieval-only mode with no
  `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` configured. The Anthropic code path,
  the grounding prompt's effect on a real model, and citation correctness have
  never been exercised against a live API.
* **Streamlit was not run against real papers.** The 25 app checks used the
  AppTest harness with a stub encoder and the synthetic corpus.
* **The offline suites use a stub encoder.** Any retrieval numbers they print
  come from a hashed bag-of-words stand-in and are a code-correctness signal
  only. They are not, and must never be reported as, system performance.

**Net position after this run:** the software runs end to end with the real
embedding model. Nothing is yet known about how well it retrieves from real
biomedical literature.
